## 1. 料金プラン設計

### 1.1 無料プラン（Free）

| 項目 | 内容 |
|---|---|
| アラーム登録数 | 1つ |
| 解除ミッション | スクワット・腕立て伏せ（各10回固定） |
| アラーム音 | デフォルト1種のみ |
| 音量設定 | 変更不可（最大音量） |
| 統計・記録 | なし |
| カメラリロード | あり（バグ改修のため無料でも必須） |

### 1.2 有料プラン（Premium）

| 項目 | 内容 |
|---|---|
| 月額 | 500円 |
| 年額 | 4,500円（月額比 1,500円お得） |
| 無料トライアル | 7日間 |
| 課金基盤 | StoreKit 2 / `in_app_purchase` パッケージ |

### 1.3 Premium で解放される機能

| 機能 | 詳細 |
|---|---|
| 解除ミッション追加 | バーピー、勉強カテゴリ（読書・学習）等 |
| 回数カスタマイズ | 最低5回〜上限は種目ごとに設定（後述） |
| アラーム音カスタマイズ | アプリ内蔵の追加音源（3種以上）から選択可能 |
| iOS音楽ライブラリ連携 | デバイスの音楽をアラーム音に設定可能（※1） |
| 音量調整 | アラーム音量を下げる設定が可能 |
| 達成統計 | 成功/失敗カウント、連続記録、履歴一覧 |
| SNSシェア | 連続達成記録をSNSにシェア可能 |

> ※1 iOS音楽ライブラリ連携について：
> Apple の MusicKit を利用すれば技術的に実現可能。ただし以下の制約あり。
> - Apple Music サブスク加入者 → ストリーミング楽曲も選択可能
> - 未加入者 → デバイスにローカル保存された音楽のみ選択可能
> - ユーザーに「メディアとApple Music」の権限許可が必要
>
> MVP追加フェーズでは **優先度低** とし、まずアプリ内蔵音源の追加を優先する。

## 2. 解除ミッション体系の改修

### 2.1 「解除項目」の名称について

「解除項目」「種目」だとやや堅い印象があるため、以下の候補を提案する。

| 候補 | ニュアンス | おすすめ度 |
|---|---|---|
| **モーニングミッション** | ゲーム感覚。「朝のミッションをクリアせよ」 | ★★★ |
| **めざましチャレンジ** | 日本語で親しみやすい。チャレンジ感がある | ★★★ |
| **解除チャレンジ** | 「アラームを解除するためのチャレンジ」で直感的 | ★★☆ |
| **ウェイクアップアクション** | 英語寄り。スタイリッシュだがやや長い | ★★☆ |
| **朝の試練** | コンセプトに合う。コピーライティングとの相性◎ | ★★☆ |

> 決定はデザイン・コピーライティングのフェーズで確定してよい。
> 本ドキュメントでは仮称として **「モーニングミッション」** を使用する。

### 2.2 カテゴリ構成

```
モーニングミッション
├── 💪 筋トレ
│   ├── スクワット     【無料】
│   ├── 腕立て伏せ     【無料】
│   └── バーピー       【Premium】
│
└── 📖 勉強
    ├── 読書（本を映す）  【Premium】
    └── 学習（ペンを映す） 【Premium】
```

- 将来的にカテゴリは拡張可能な設計とする（例：🏃 運動、🧘 マインドフルネス 等）
- 各ミッションにはアイコンを設定し、視覚的に区別する

### 2.3 検出方式の整理

| カテゴリ | ミッション | 検出方式 | 判定基準 |
|---|---|---|---|
| 筋トレ | スクワット | ポーズ推定（ML Kit） | 膝角度の変化で1回カウント × N回 |
| 筋トレ | 腕立て伏せ | ポーズ推定（ML Kit） | 肘角度の変化で1回カウント × N回 |
| 筋トレ | バーピー | ポーズ推定（ML Kit） | 立位→伏臥位→立位を1回カウント × N回 |
| 勉強 | 読書 | 物体検出（ML Kit Object Detection） | カメラに本が映った状態を一定時間（例：10秒）維持 |
| 勉強 | 学習 | 物体検出（ML Kit Object Detection） | カメラにペンが映った状態を一定時間（例：10秒）維持 |

> **勉強カテゴリの技術的留意点：**
> - ML Kit の物体検出は汎用的な物体を検出するが、「本」「ペン」を正確に分類するには
>   カスタムモデル（TFLite）の導入が必要になる可能性がある
> - まずは ML Kit の標準物体検出で検証し、精度が不十分な場合はカスタムモデルを検討
> - 代替案：物体検出ではなく画像分類（`google_mlkit_image_labeling`）で
>   「book」「pen」ラベルのconfidence値を閾値判定する方法もある

### 2.4 回数カスタマイズ（Premium）

| ミッション | 最低回数 | デフォルト | 上限（推奨） |
|---|---|---|---|
| スクワット | 5回 | 10回 | 50回 |
| 腕立て伏せ | 5回 | 10回 | 30回 |
| バーピー | 5回 | 5回 | 20回 |
| 読書 | — | 10秒間維持 | 60秒間維持 |
| 学習 | — | 10秒間維持 | 60秒間維持 |

## 3. 達成統計機能（Premium）

### 3.1 記録する項目

| データ | 説明 |
|---|---|
| 日付 | ミッション実行日 |
| 選択ミッション | どのミッションで解除を試みたか |
| 結果 | 成功 or 失敗（10分タイムアウト） |
| 解除までの所要時間 | アラーム発動から解除完了までの秒数 |
| 連続成功日数 | 現在の連続記録（ストリーク） |

### 3.2 統計画面の表示内容

- 今月の成功率（成功回数 / 試行回数）
- 連続成功日数（現在のストリーク）と最長記録
- カレンダー形式での成功/失敗表示（GitHub の草のようなイメージ）
- ミッション別の実施回数

### 3.3 SNSシェア機能

- 連続達成が一定日数（例：3日、7日、14日、30日、100日）に到達した際にシェアを促す
- シェア画像を自動生成する（アプリ名 + 連続日数 + デザイン）
- 対応先：iOS標準のシェアシート（`share_plus` パッケージ）を使用
  - X (Twitter)、Instagram ストーリーズ、LINE 等、OS側で対応しているものすべて

## 4. バグ改修：カメラリロード機能

### 4.1 概要

- 筋トレ検出画面にリロードボタンを追加する
- カメラがうまく認識しない場合にユーザーがリロードできるようにする
- **無料プランでも必須の改修**

### 4.2 仕様

| 項目 | 内容 |
|---|---|
| リロード操作 | 画面上のリロードボタンをタップ |
| リロード時の動作 | カメラセッションを破棄→再初期化→ポーズ検出を再開 |
| 10分タイマーの扱い | リロード時にタイマーをリセット（再度10分カウント開始） |
| 回数カウントの扱い | リロード前のカウントは保持する（0にリセットしない） |
| リロード回数の制限 | 制限なし |

> **注意：** タイマーリセットにより、理論上は無限にリロードし続けてアラームを回避できる。
> ただしアラーム音が鳴り続けている状態のため、実質的な悪用リスクは低いと判断する。
> 必要に応じてリロード回数上限を設けることも将来検討可能。

## 5. アラーム音の拡充

### 5.1 アプリ内蔵音源（優先度：中）

| 音源 | プラン | 備考 |
|---|---|---|
| デフォルト音（現行） | 無料 | 変更なし |
| 追加音源 A | Premium | けたたましい系（例：目覚まし時計風） |
| 追加音源 B | Premium | 不快系（例：工事現場風） |
| 追加音源 C | Premium | 緊張感系（例：緊急アラート風） |

- 音源は MP3 形式、数秒〜30秒のループ再生
- 設定画面でプレビュー再生→選択の流れ

### 5.2 iOS音楽ライブラリ連携（優先度：低）

| 項目 | 内容 |
|---|---|
| 実現可否 | **実現可能** |
| 技術 | Apple MusicKit / `NSAppleMusicUsageDescription` |
| 対象 | デバイスにローカル保存された楽曲 + Apple Music加入者はストリーミング楽曲 |
| 必要な権限 | 「メディアとApple Music」へのアクセス許可 |
| プラン | Premium 限定 |
| 実装優先度 | 低（内蔵音源の追加を先行。ユーザー需要を見て判断） |

## 8. 技術的な追加考慮事項

### 8.1 データ永続化

データの種類に応じて保存先を使い分ける。外部サーバー（Firebase等）は現時点では導入しない。

| データ種別 | 保存先 | 用途 |
|---|---|---|
| アプリ設定 | `shared_preferences` | アラーム時刻、選択ミッション、音量設定等 |
| 統計データ | `sqflite`（SQLite） | 成功/失敗記録、連続日数、履歴 |
| サブスク状態 | StoreKit 2（デバイス側） | 課金状態の検証 |

#### 統計テーブル設計（参考）

```sql
CREATE TABLE mission_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  date TEXT NOT NULL,           -- 実行日 (YYYY-MM-DD)
  mission_type TEXT NOT NULL,   -- スクワット / 腕立て伏せ / バーピー / 読書 / 学習
  result TEXT NOT NULL,         -- success / failure
  duration_seconds INTEGER,     -- アラーム発動から解除までの秒数（失敗時はNULL）
  created_at TEXT NOT NULL      -- レコード作成日時
);
```

> **将来的な拡張について：**
> 機種変更時のデータ引き継ぎやランキング機能等が必要になった場合は、
> Firebase（Firestore）を追加導入し、ローカルDBのデータを同期する設計で対応可能。
> SQLiteで始めることで、後からの移行も容易。

### 8.2 サブスクリプション実装

- `in_app_purchase` パッケージ（Flutter公式）を使用
- App Store Connect でサブスクリプション商品を登録（月額・年額）
- 無料トライアル7日間は App Store Connect 側で設定可能
- レシート検証はサーバーサイドが推奨だが、MVPではデバイス側検証（StoreKit 2）で対応可能
